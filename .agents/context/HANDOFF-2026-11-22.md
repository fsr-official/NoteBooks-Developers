## 2. Renderer architecture

**Current Markdown reader:** `NoteBooks-Framework/src/lib/markdown/renderer.ts` uses Markdown-it with footnotes, sub/superscript, task lists, Obsidian syntax, callouts, search/section metadata, and `markdown-it-texmath` + KaTeX. It emits HTML and inert visual placeholders/figure metadata for Mermaid, TikZ, Desmos 2D and Desmos 3D. A Mermaid fence whose first meaningful line is `mindmap` is tagged `data-diagram-type="mindmap"`. `src/components/next-markdown-reader.tsx` loads the reader-side visual runtimes on demand. Mindmap-specific viewing is implemented in the vendored `NoteBooks-Developers/utils/obsidian-markdown-it.js`.

Math delimiters supported by the production Markdown readers include `$...$`, `$$...$$`, `\(...\)`, `\[...\]`, and `\begin{...}...\end{...}`. The Framework's `src/lib/markdown/mdx-compiler.ts` is a separate experimental MDX path; do not treat MDX as the normal content authoring format or enable its reader globally without following the V2 plan and feature gates.

**Developers static build:** `NoteBooks-Developers/utils/build.ts` parses the pilot source into the chapter bundle; `utils/markdown-renderer.ts` renders regular Markdown pages and compiles Desmos fences; `utils/build-html.ts` creates mirrored static HTML and manifest records; `utils/build-diagrams.ts` uses Playwright + local Mermaid/TikZ assets to render SVGs. `utils/audit-html.ts`, `audit-desmos.ts`, and `audit-build.ts` perform separate audits. The Framework has a precompiled HTML reader under `src/components/precompiled-html-reader/`; this does not replace the ordinary Markdown renderer.

## 3. Conventions and decisions

- Stay on each repository's current branch; do not create or switch branches, commit, or push without explicit user direction. The Framework was on branch `whoami`; Developers and all three content repos were on `main` at handoff. Confirm with `git status` before touching anything.
- Preserve unrelated dirty work. In particular, Framework has pre-existing reader-navigation/precompiled-HTML edits; Science has pre-existing Physics 08 NOTES/CNOTES/GLOSSARY edits. Do not revert or fold these into unrelated changes.
- Keep curriculum sources as Markdown and use syntax the current Markdown readers support. For equations use standard LaTeX delimiters, not plain text pretending to be math. Keep a multi-step worked solution readable: one bold step label per paragraph, followed by its own displayed equation when appropriate.
- CNOTES should be genuinely chapter-specific: a Mermaid `mindmap` plus section-organized summaries and important facts. Avoid empty placeholders and generic boilerplate. Use formulas only when relevant to the subject. Preserve existing substantive content; flag uncertain source facts rather than guessing.
- Existing source PDFs are not always aligned with chapter filenames. Check the first-page chapter title (e.g. `pdftotext`) and matching notes/exemplar before relying on one.
- Avoid publicizing or copying textbook passages; summarize and respect each content repository's rights.

## 6. Failed attempts and useful lessons

- The content repositories are under `NCERT-REPOSITORIES/`, not workspace-root `FILES/`; `git -C FILES/NCERT-*` failed from the current workspace.
- `tsx --eval` defaults to CJS here; top-level `await` fails. Wrap async evals in an async IIFE, or use `node --import tsx --input-type=module -e` for ESM modules with top-level await.
- Importing Mermaid and calling `mermaid.parse()` directly in Node failed (`DOMPurify.addHook is not a function`). The repository's browser-based `buildDiagrams()` is the working validation path.
- A TypeScript test using a template literal containing triple-backtick Markdown failed parsing; construct such fixtures as an array of lines joined with `"\n"`.
- Ripgrep rejects a literal `\n` unless multiline mode is enabled. Use `multiline: true` or a different pattern.
- One CNOTES render audit exposed the malformed Physics 07 formula above; it was corrected and the complete 142-file audit passed.
- Local renderer/build checks do not prove GitHub Actions, production secrets, QStash, Desmos network access, or deployed index freshness.

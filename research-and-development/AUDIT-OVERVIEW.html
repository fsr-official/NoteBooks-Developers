NoteBooks Repository Audit — 2026-11-22

Scope: Read-only source and test audit of NoteBooks-Framework, NoteBooks-Developers, and the three NCERT content repositories.

Status: Source-confirmed and test-confirmed findings are complete for the available evidence. Browser verification was limited to the local production home page at desktop and phone widths. Supabase, QStash, Vercel, Redis, GitHub Actions, and live browser behavior remain production-verification items.

Executive verdict

The repository is structurally mature and has substantial focused test coverage:

  • Framework: 60 test files passed, 236 tests passed, 2 skipped.
  • Framework typecheck passed.
  • Framework production build passed.
  • Developers: 37 focused build/parity tests passed.
  • Developers typecheck passed.
  • Local browser check found no JavaScript console errors at desktop or mobile width on the home page.

The highest-risk source-level issue is operational: repository reconciliation can enqueue repeated jobs and lacks an idempotency/deduplication contract. The strongest user-facing inconsistency is architectural: Markdown, runtime MDX, static HTML, and React chapter-bundle readers maintain separate contracts and can drift. The most concrete mobile/accessibility issue is missing modal focus management in both AI drawer implementations.

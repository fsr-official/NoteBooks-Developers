Scope and limitations

The checks were read-only. No production writes, queue publishes, credential/configuration changes, or migrations were performed. These are connected-provider/account observations, not a production certification of the deployed Vercel app. Deployment linkage, app credentials/region binding, worker completion, and runtime behavior remain unverified. Sensitive credentials, URLs, and user data were not included.

Vercel

  • Record latest deployment commit and route env configuration.
  • Verify APP_BASE_URL, WEBHOOK_SECRET, REPOSITORY_RECONCILIATION_SECRET, QSTASH_*, SUPABASE_*, KV_REST_*, GITHUB_*, TRUSTED_MDX_REPOSITORIES, and DESMOS_API_KEY presence without exposing values.
  • Review function logs for /api/webhooks/repository-update, /api/cron/repository-reconciliation, /api/workflows/repository-update, /read, and /api/raw.
  • Confirm route cache headers and static/dynamic rendering match intended routes.
  • Check memory, duration, and invocation volume for repository worker runs.

QStash

  • Inspect delivery/retry/DLQ logs for all five repository-update shards.
  • Record queue backlog, oldest message age, failure count, retry exhaustion, replay count, and message-ID correlation.
  • Verify current/next signing keys match publisher and worker configuration.
  • Compare signed GitHub webhook timestamps with final sync-run timestamps.
  • Check whether reconciliation curl retries and QStash retries create duplicate deliveries.

Supabase

  • Run migration-history and advisor review.
  • Confirm RLS policies and effective grants for public, authenticated, and service-role accounts.
  • Inspect Postgres logs for RPC locks, sync trigger failures, slow statements, RLS denials, and run-table insert/update failures.
  • Compare live constraint definitions with migration replay.
  • Check row counts/trends for repository_sync_runs, ai_usage_events, ai_provider_key_metrics, API metrics, and audit events.
  • Check backup/PITR configuration and recovery status.

Redis

  • Confirm public-index TTL/content after a known repository push.
  • Verify GitHub commit SHA, repository file SHAs, and Redis index entries agree.
  • Check cache hit/miss behavior for /api/raw, compiled HTML, and chapter bundles.
  • Inspect Redis latency, command cost, memory, eviction, and stale-key patterns.
